It differs per skill, not per session as a whole — here's the actual mechanism, confirmed from the code:

Every one of the 20 questions is an independent fresh call to skill.generate(rng) — question 2 isn't derived from question 1, it's a brand new random draw from scratch, same as question 1 was. So whether the kind stays the same or changes across those 20 questions depends entirely on whether that particular skill's generate() function has branches that return different kinds:

Most skills are "kind-stable" — every branch inside them returns the same kind, so all 20 questions in a session are the same interaction type, just with different numbers/words each time. E.g. phrasal-verbs is always multiple-choice, debate-terms is always click-match, area-of-shapes is always fill-blank even though it cycles through rectangle/square/triangle/circle.
A few skills are "kind-mixed" — Pythagoras is the current example: its "is this a right triangle?" branch returns multiple-choice, but its "find the missing side" branches return fill-blank. So within one 20-question Pythagoras session, question 4 might ask you to type a number and question 5 might ask you to pick yes/no — genuinely different interaction types back-to-back, because the random branch pick differs each call.
So it's not "random" in the sense of an independent dice roll for kind — it's a consequence of whatever branching that skill's author (me) built in. If I want a skill to always feel the same interaction-wise, I keep every branch on one kind (like area-of-shapes does). If mixing kinds is pedagogically useful, I let branches diverge (like Pythagoras does).

How I actually work each round

Research the requirement first — I read the strand descriptions in curriculum.ts (that's the CBC syllabus breakdown) and look at what's already built for that subject, so new skills fit the same shape/quality as existing ones rather than reinventing conventions.
Design the content model before writing generator code — for each skill I decide: what's the data bank (verb lists, passages, term/definition pairs, shape formulas), what varies per-call (numbers, which branch/mode fires), and what's fixed. This is the "template" — a pure function that takes randomness in and returns a fully-formed question.
Write it, then fuzz it — I spin up a throwaway API route that calls generate() 500 times per skill and checks structural invariants (no duplicate choices, correct answer key always maps to something real, etc.), then delete the route. This catches "the 400th random combination produces a broken sentence" bugs that eyeballing a few examples won't.
Typecheck, lint, then look at it in a real browser — screenshots plus a scripted interaction pass, not just "it compiles."
Your actual question — adding variety later

You spotted it correctly: areaOfShapes currently does rectangle, square, circle, and right-triangle — no trapezium, parallelogram, or compound/composite shapes. There are three tiers of "more variety," increasing in cost:

Tier 1 — add a branch to an existing skill. Adding a trapezium mode to areaOfShapes is exactly this: one more if (shape === "trapezium") branch with its own formula, distractors, and explanation. Cheapest, no architecture touched. This is how pythagoras already has 3 modes and linearInequalities has 3 solving forms.
Tier 2 — add a whole new skill file. If a topic deserves its own dedicated practice session rather than being one mode among several (e.g., "Volume of solids" as its own skill, separate from flat-shape area), it's a new file + one line in skills/index.ts. This is what all 40 skills so far have been.
Tier 3 — extend the architecture itself. Only needed when the existing building blocks can't represent the new thing at all. Two examples from this project already: adding the passage field to show reading text (English/Kiswahili reading skills needed it), and fill-blank numeric answers (used first by math, now reused by Social Studies' map-scale skill). A trapezium is not this tier — the VisualSpec type already has a generic-enough shape story that a new shape mostly slots into Tier 1; something like "draw a compound L-shaped floor plan" might eventually need a new visual type, which would be Tier 3.
So: nothing about the current 40 skills is a ceiling. If you come back later and say "add circles/trapeziums to the geometry skill" or "I want a whole new probability-tree skill," it's Tier 1 or Tier 2 — same fuzz-test-then-verify loop, no rework of what exists. Tier 3 only comes up when a genuinely new interaction or visual shape is needed, and even then it's additive, not a rewrite.
